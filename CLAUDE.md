# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What Geode is

Geode is the everything-tool for an index exotic equity derivatives desk: risk, pricing, execution, and data visualization in one permanent, keyboard-driven shell, built in Rust on gpui (Zed's UI framework) + gpui-component.

**Where the detail lives.** `docs/phase-history.md` is the verbatim, phase-by-phase record: what each phase built, every user ruling, every review finding and every "a maintainer must not tidy this" trap, in the order they landed. It is the file this section used to be, and it is long on purpose. **This file has a size cap, so when a phase or ruling merges, add its paragraph to `docs/phase-history.md`, a row to the status table and any new load-bearing rule to the list below — never a narrative paragraph here.** The rules below are the ones most likely to be tripped over without reading that record; the history has the reasoning, the harness entries and the test names behind each.

Two documents govern all work and are worth reading before non-trivial changes:

- `docs/PHILOSOPHY.md` — the charter. Key rules: Geode is a lens, not a brain (no financial computation in-app, only view-shaping); every action must be keyboard-reachable; nothing may stall the render thread; data-oriented design throughout (struct-of-arrays, allocation-free hot paths, per-frame heap churn is a defect).
- `docs/superpowers/specs/2026-08-28-geode-foundation-design.md` — the full architecture spec (section references like "spec §7.4" in code comments point here). Implementation plans live in `docs/superpowers/plans/`.

### Load-bearing rules

Each bullet is a rule the code depends on and a test or harness entry usually pins; the history explains why. The "Workspace invariants and gotchas" section further down holds the ones about the build, focus, and the pinned gpui-component.

**Config, themes, logging**

- A theme's name carries its own light/dark (`Gruvbox Light` and `Gruvbox Dark` are two themes). `[theme] mode`, the `mod+shift+t` toggle and the Dark-mode row were retired (2026-09-12); a leftover `mode` key warns and is removed by the next pick.
- `keymap.mod = "ctrl"` is refused with an error at load and reload (falls back to the default alias) rather than documented as colliding — a user ruling.
- `toml`'s `preserve_order` is on workspace-wide: a schema's column order is file order everywhere it is iterated.
- `[log]` sets levels by `geode::*` target suffix; every third-party crate is capped at `warn` regardless of `[log] default`. The daily log file and crash file names roll on the UTC date; every *displayed* time is the trader's CONFIGURED clock — `[time] zone` (IANA name, the machine's zone by default), `sod`/`eod` beside it (as-of dialog ruling 2026-09-20) — including `HH:MM` as-of input; `chrono::Local` is banned workspace-wide (`clock::tests::no_crate_uses_chrono_local`) and every formatter takes a `geode_core::clock::Clock`. The daily log and crash file names still roll on the UTC date.
- `geode_shell::config_write` is the one door a config write goes through; no module opens a config file itself. Every keyed persist spawns its write unordered (known race; fix belongs in `config_write` for all of them at once).
- `ShellServices.keymap_diagnostics` and `keymap_fragment_diagnostics` ride from `main.rs` into the diagnostics config section because they cannot be recomputed from the config alone; `apply_reload` folds the fragment diagnostics **after** `reload::decide`, so a dropped fragment binding is visible but can never reject a trader's config.

**Data layer**

- Health (`HealthTracker`, `geode-data/src/service.rs`): two lanes per source, `discovery` (content-blind) and `load` (content-aware, keyed by BATCH, worst-across-batches); the worse by `severity_rank` (`Failed` > `Degraded` > `PendingTooLong` > `Pending` > `Ok`) wins, an equal rank goes to the slot that CHANGED most recently, and the deciding slot's own detail is forwarded. Deciding and emitting are one step under the lock (`report_*_and_emit`; bare `report_*` is test-only), and a transition counts as reported only once delivered. `DataService::open` seeds the load lane from `Catalog::live_health` before `Scheduler::spawn`: no time bound (`AsOf::Live` has none), `gen_id desc` tie-break (a corrected republish ties its predecessor's `source_time`), and the four unhealthy labels named explicitly (`from_parts` maps an unknown label to `Ok`).
- An `EventSink` returning `false` means "not delivered"; no producer stops on it. `make_sink` logs a closed receiver once and only counts a full channel.
- Every background boundary (ingest load, catalog recheck, discovery poll, query worker, document publish, message receive) runs under `geode_core::panic::contained`; a contained panic logs and keeps the app running, an ingest load panic marks the source `Failed`.
- `IngestEvent::Published`/`Failed` carry the source name, and a degraded publish reaches the entity as `DataEvent::Health` — key by source, never by dataset.
- Document family (`family = "document"`): key columns must be `utf8`, dimensions must be in `key`, a column named `book` is refused, types are f64/i64/utf8/date only (a VALUE column too, since 2026-09-20: the dividend schedule and the pricer's sheets both store dates and text per row; `timestamp`/`bool` have no `document::Value` and are refused), a zero-row document is refused, `document_columns()` is the one column order storage and requests share, and the joined key (`KEY_SEPARATOR`) is the batch. A document's as-of pins its OWN generation and reports its own `source_time`; live freshness is `live_source_time(dataset, batch, None)`, never the dataset-wide fold. `compile_document` does not cast the key to its ENUM (known, not a correctness item).
- Grain-free scope lowering (`document_select`): a text filter with no surviving term compiles to literal `false`; a selection or expression conjunct naming a column the dataset has no storage for is dropped, never `false` and never a binder error. `ScopeSemantics::NotApplicable` exists but no query produces it yet.
- Adapter tier: `ChannelAdapter` holds its inbound sender weakly; `SubscriptionWorker` holds the refused COUNTER, never a `MessageSink` clone (a sink is a sender and would keep the bus open through shutdown). The runner pops a queued document ahead of any file. `ConnectionState` maps to the discovery lane; parse/validate/`source_time_of` failures go to the load lane keyed by batch or, when unparsed, by topic, and `Receiving::failed_topics` is how a topic-keyed failure ever clears. An unservable subscribed source is `Failed` on the discovery lane at `DataService::open` and is NOT a config-section diagnostic (known gap).
- `Coalescer<T>` is pure latest-wins-per-key; every method takes `now`. A key's first offer in a window releases at once and each release restarts that key's window.
- The demo bus publishes every underlying at start then one key per `cadence ± jitter`, so per-key republish is roughly `cadence × keys`.
- Series family (`family = "series"`): five implied columns in `SERIES_COLUMNS` order, never declared (a declared one is an error and is dropped), and `create_series_tables_sql` generates its column list by zipping that constant with `SERIES_TYPES`. Live is `arg_max(value, received_at)` per `(source, series_id, ts)` — there is no live/archive pair and no generation — and `append_series` is the ONE door rows enter by: it drops a staged row equal to the LIVE value for its ts before inserting, writes a coverage row even for an empty fetch, and runs that pair's retention sweep inside the same transaction (`sweep_pair`; there is no production sweeper anywhere else). Both timestamps are naive UTC `TIMESTAMP`, bound and read as epoch micros (`make_timestamp`/`epoch_us`), so no session time zone can shift them. A `retention`/`history` window that is not a duration STRING, or whose micros do not fit an `i64` (`parse_duration` accepts `y`), is an error diagnostic at `datasets.<name>.<field>` and unbounded; reached anyway by a hand-built `DatasetSpec`, an unrepresentable window sweeps NOTHING — `series::cutoff` converts rather than casts, the same "unrepresentable means no clip" answer `DataService::fetch` gives on the request side; cast, it wraps negative and deletes the pair's whole table and coverage.
- A fetch source is `SourceShape::Fetch` (a non-directory adapter over a series dataset); `is_subscribed()` still means only "not a directory". `DataService::fetch` clips the request to the dataset's `history` window BEFORE subtracting coverage (a span older than it would be appended and swept in one breath, coverage row included), then queues one `FetchWork::Span` per gap; every early exit is a `SeriesFetched`. The load-lane key for a series is `"{identity}@{source}"` on every path — the fetch worker's `Failed` and the runner's `SeriesAppended`/`SeriesFailed` — which is what lets a success clear a failure. `DataEvent::SeriesFetched` is keyed by the pair, never by the asking tile, and `Ok(0)` still means requery (the span is covered, whether just now or already). A `Fetch` source has no connection state, so a servable one is `Ok` on the discovery lane at `DataService::open`. The diagnostics sources section paints a source's two detail rows by `SourceSummary::shape`, resolved once in the app bridge (the last place holding a `SchemaSpec`) — a fetch source is `adapter` plus `fetch`, never an empty `topics:`; neither `adapter` nor `topics.is_empty()` can tell the two non-directory shapes apart.
- Series query (`geode-data/src/query/series.rs`): one `SeriesPlan` per request — points over the UNION of the SOURCE slots' buckets with a `NULL` read back as `NaN` (`nan_if_null`, never `0.0`), an expression over the INNER join of its operands with a guarded division (`case when den = 0 then null`), one percentile and one bins statement PER SLOT over the window, each re-running the shared CTE prefix (`docs/perf.md` has the cost and the grouping-sets fallback), and one coverage statement per source slot. Every string and timestamp is bound; the percentile fractions, the bin count and an expression's numeric literals are formatted into the text — range-checked in `validate`, finiteness-checked in `lower`, which is why a non-finite literal is a refusal; only table names, the interval, the aggregates and `s{n}` are otherwise text. The bin index is `width_bucket` spelled out — the pinned DuckDB has no such function — and its `least(.., k)` is what keeps the window's maximum out of bin `k + 1`, where the reader would discard it. The cap is checked BEFORE compilation (`DataService::series`). `Delivery::Series` routes by key; `Delivery::SeriesFetched` answers `Delivery::key() -> None` and `ShellView::deliver` hands every VISIBLE occupant (`visible_tile_keys`) its own copy — a hidden tile holds no subscription and requeries on `set_visible(true)`.
- `Payload::{Snapshot, Series}` and `Work::{Query, Series}` in the pool: coalescing, interruption and containment never look inside. `RequestKind::Series { pairs }` carries every source slot's `(slot, source, identity)` so the result sink attaches each pair's `load_lane` health BY SLOT NUMBER (the slots and the pairs differ in length the moment a request has an expression). That sink reads the tracker under the pool's queue lock: the order is pool queue lock → tracker lock, never the reverse.

**Shell: frame, tiles, diagnostics**

- Every scope, grouping or as-of mutation opens a flip barrier; tiles stage and promote together, released once every awaiting tile has arrived or at 250 ms. `FrameVersions.flip` is excluded from every tile's `follows_changed`. A non-placeholder occupant that never requeries must still self-arrive (the diagnostics tile held every blotter to the deadline until 2026-09-14).
- `Diagnostics::watch()`/`request_catalog()` queue a request but never `cx.notify()`; the caller must, in the same update. `frame_hist` is copied only on the ~500 ms reload-poll tick and only while `watchers() > 0`. `DiagVersions` is one counter per section so a perf tick never rebuilds the config section. The config section is seeded identically by `ShellView::new` and `apply_reload` (five groups, same order: config, mod alias, `modules.default`, `[time]`, keymap).
- A bare double-click on a PLACEHOLDER tile opens the tile picker through `try_pick_tile_on_double_click` (`drag.rs`), called by both tile listeners between the fullscreen door and the drag arm, and the EMPTY-TREE hint (`empty-hint`) has the same door (`try_pick_on_empty_tree_double_click`) — a fresh session has no tile, so a door on occupants alone leaves the first screen deaf; the empty DOCK hints have it too, with every click first moving the region onto that dock through `Workspace::focus_empty_dock` (the mouse's door; `focus_dock` stays the directional rule and refuses an empty dock) so the pick lands there; it is gated on that placeholder being the FOCUSED tile (a first click on an occluding divider or backdrop never reaches the listener, and the pick lands on the focused tile) and returns true so the click-to-focus tail does not re-arm `pending_focus_restore` (which would take the picker's field focus a frame later) — a double-click on a real tile is left to its module. `ShellView::open_module(kind)` focuses an existing occupant or adds one via `add_tile`; `pending_tiles` is keyed by `TileId`, `unplaced_records` by the raw `u64`, both retained to live tiles in `ensure_occupants`, which creates tiles in sorted `TileId` order.
- `Delivery` is matched exhaustively by every occupant with no wildcard arm; add a variant and the compiler names every site.
- `ModuleFactory::contexts()` is separate from `kind()` (the panel factory is kind `cvi`, context `marketdata`); a fragment predicate must be a plain conjunction whose first identifier is one of the factory's contexts.
- **A `:` line changes only its own tile (2026-09-20).** Every module's vocabulary is swept by an `every_colon_command_leaves_…` test (the frame's counters, `take_pending_persist`, `take_pending_scope_persist` and `Diagnostics`'s pending requests, whichever the module's own vocabulary can reach); a word that used to be frame-wide is `Command::Refused(&str)` naming its door and is never a completion. The blotter's `TileAsOf` is the third override beside `Pin` and `tile_scope`: `differs_on_followed` compares `as_of` only while `Follow`, `requery` reads the pin, the neutral chip paints from `tile_as_of` (cached strings via `set_tile_as_of`) and suppresses the provenance warning chip, and the session key is `as_of` (`"live"` or RFC 3339). `scope_expr_view::open` seeds the field AFTER the dialog door (the door resets it). `Target::LogLevel` is two steps in one modal: `escape` on the level step goes back, not out.
- Scope bar: chords (ctrl/alt/cmd) dispatch from the text field against the `workspace` context alone; an overlay opened from the field returns focus to it on close. A selection chip's `×` is a child of the chip whose body opens the picker, and `occlude()` on the `×` is the ONE thing that keeps a drop from also opening it (gpui gates every mouse listener on `hitbox.is_hovered`; an occluding child hides the parent's hitbox) — do not add a `stop_propagation` beside it, and do not drop the occlude for one. The `×` takes the CHIP's pointer states, not the bare glyph's, because the body it sits in is at rest while the pointer is on it.
- Tile stacks (`Node::Stack`, `tiling/tree.rs`): `layout_node`/`collect_visible` emit only `children[*active]`; `Tree::set_focus` is the one door focus is assigned through, and a focused member is always its stack's active member. `TileContent::set_stack`/`title` are required, not defaulted; `set_stack` fires on the first render and on every `(index, len)` change, never otherwise (`stack_sent` records a tile only AFTER its handle was delivered). Unstacking (`pop_out`) reuses the CLOSE rule via the same `remove_leaf` `Stack` arm — no separate "first survivor" behaviour — and clears fullscreen unconditionally, like `split`. A centre drop now joins the target's stack (`Workspace::drop_stack`), not a swap; keyboard `move_direction` still pops a stack member out. `Tree::contains` is a non-allocating recursive walk (`holds_anywhere`), not `self.tiles().contains(&id)` — `stack_position` calls it per tile, per workspace, per dock, every render. Session encodes `kind = "stack"`/`members`/`active`; `Tree::from_parts`'s `validate_node` heals a hostile one (dedupes, clamps `active`, collapses to a leaf) rather than refusing it, and an older build with no `"stack"` arm refuses the whole tree, not just that node.
- Palette ranking: match text is `"{title} {category}"` with category scores halved (`CATEGORY_DIVISOR`), plus a frecency bonus capped at `MAX_BONUS` = 18. Read `a_used_category_hit_leads_a_short_title_prefix_and_loses_to_a_long_one` before moving any of the three constants. Only palette dispatches count; usage persists in `session.toml`'s `[palette.usage]` through the layout's own flush (a separate file would trigger a config reload per dispatch).

**Pricer (Parts 1–2)**

- The vocabulary and `Pricer` trait are `geode_core::pricing`; `geode-pricing` is implementations only (a leaf; the shell never depends on it). A calculation lives in the binary only as such a leaf, behind the request/outcome door — PHILOSOPHY §1 "In-process calculation".
- The pricing worker is one thread beside the pool: latest wins per key, `Cancel { key }` stops at the next line boundary and delivers what was priced, `catch_unwind` + `contained` per line. `pricer: None` errors every line with `PricerConfig::missing_reason`.
- Overrides are STATEFUL (`Pricer::set_overrides` then `price`) and batch-scoped by the worker — set once per batch before its first line, never per line; a refusal or a panic there fails every line of the batch (`overrides refused: <reason>`) and prices none of them, rather than pricing some lines against the wrong market data.
- A batch the worker's own bounded queue refuses is still answered: `DataService::price` emits the `DataEvent::Price` itself with an error per line — `DataHandle::price`'s `false` means only that the request channel refused, never that a submitted batch went unanswered.
- `Request::Publish` is refused unwritten for a non-`local` dataset; a local publish is source `LOCAL_SOURCE`, emits `Published` + `LoadEnded` and never `Health` or `Started`/`Loading` (a sheet autosave must never blink the ingest progress strip — the runner's document arm skips `Started` when `job.source == LOCAL_SOURCE`); the bridge skips `Frame::note_published` for a local dataset (`Bridge.local_datasets`). A `[sources]` entry naming a local dataset is an error.
- A `[pricing] adapter` change is a restart stripe (`pricing_baseline`), like `sources`/`datasets` — narrowed to that one key because `refresh` is a live sheet setting from Part 3 onward and must never demand a restart.
- The worker clears `cancel_running` both when a batch is picked up and after it finishes — the two clears are REDUNDANT by design, neither alone is load-bearing (either one resets the flag before the next batch starts), and only `a_cancel_of_a_running_key_does_not_stop_the_next_batch` pins the pair; there is no separate harness entry because mutating either clear alone survives.
- `geode-pricer` (Part 2) is core only: it depends on `geode-core` alone and the app does not yet depend on it. `Sheet::apply(Edit)` is the ONE mutation door (plus the result-landing pair `deliver`/`deliver_all` and `fold_packages`) and nothing on a `Sheet` that feeds `request()` is publicly writable — `sheet_shift` and `overrides` are `pub(crate)` behind the `sheet_shift()`/`overrides()` readers, because a direct write would change every inheriting line's effective request with no stale mark; `name`, `view` and `refresh` stay `pub` (none feeds `request()`). `apply` compares `Sheet::request(row)` before and after for the lines the edit can touch (`touched_by`) and bumps `revision` + `Stale` on a change — `SetQty`, `Move`, `Group`, `Ungroup` touch nothing; `SetSpotOverride` stales its underlying's lines EXPLICITLY because the request is unchanged by design (overrides ride in `PriceParams`). A `deliver` installs only at exactly the answered revision (`OldRevision` and `FutureRevision` are dropped). **A BATCH of results lands through `deliver_all`, never a loop of `deliver`:** `deliver` folds every package per landing, which is quadratic over a batch (3.37 ms for one reprice of a 1,200-row sheet against 175 µs, `docs/perf.md`); `install` is the shared step and `deliver_all` folds once at the end. Part 3's `Delivery::Price` arm is its caller. `Sheet::take_out(at)` returns `()`, not a `RowRecord` — a record taken after neighbouring rows have moved carries a stale parent index, so a caller reads `record(at)` BEFORE removing, never after.
- An insert position is a `Place` (`Root { at }` on a root boundary, `Leg { package, leg }`), never a bare index; the inverse of `Remove` is `Restore` carrying full `RowRecord`s (ids, results, states), so undo of a removal re-requests nothing; `Group { id: Option<LineId> }` lets undo of an `Ungroup` restore the same package id, and the inverse of an `Ungroup` on an EMPTY package is `Restore { at, rows: [its record] }` (never `Group { count: 0 }`, which `apply` refuses). `Sheet::undo` applies the inverses in order and answers the redo reversed — it is documented as NOT atomic: an inverse refused mid-batch leaves every earlier inverse applied. A package may be empty (`Fresh`, no result). Package state precedence is `Failed` > `Stale` > `Fresh`, and its result is `Some` only when every leg has one and none has failed.
- Shorthand: `IMM_MONTHS` is one constant; a month form resolves to the third Friday at parse time (a date convention, spec §6.3); `render_package` prints the template form only while the legs match the table, else one line per leg. `Sheet::shorthand(row)` round-trips through `parse` for every template and both variants.
- `cell_text` is the pure half of the grid model (`CellText { text, state }`); Part 3 colours it. `pricer_views` is atomic at depth 1 in `merge::atomic_depth`; `Views::builtin()` is the two bundled views and Part 3 pushes `BUILTIN_VIEWS` into the builtin layer. `ColumnPlan::build(view)` takes no sheet.
- Storage: `to_rows` is `None` for an empty sheet (the zero-row refusal); values have no NULL (flag + value pairs); spot overrides persist as the `spot_overrides` attribute (`UND=LEVEL;…`); `Refresh` is three-state (`""`/`off`/`30s`, and `500ms` where the interval has a sub-second remainder — `{}s` alone spells every sub-second refresh `0s`); an override key is upper-cased on the way in, as `SetSpotOverride` stores it; `from_rows` rebuilds through `Edit::Restore` and requires a package's legs to follow it CONTIGUOUSLY in `order`, not merely after it (`children` is a scan, so a leg with a root line between it and its package would land in neither `roots()` nor `children(pkg)`). A `parse`d template quantity is a `checked_mul` against the leg weight: the overflow is a parse error at the quantity token, never a wrap. `PRICER_SHEETS_DECLARATION` is the dataset's TOML, wired into the builtin layer in Part 4. Its per-row utf8 value columns rely on the document family's VALUE rule being f64/i64/utf8/date (the dividend work widened it for every document on 2026-09-20; the branch's `local`-gated exemption was dropped at the merge); Part 4 still owes a check that the DuckDB publish path quotes `order`/`kind`/`parent`/`template` as identifiers (the final review traced the DDL, staging and `compile_document` and found all three quote).

**Chart (`geode-chart`)**

- The crate depends on `geode-core`, `gpui`, `gpui-component` and `chrono` and nothing else (`geode-shell` is a dev-dependency, for the theme sweep); `core::DESIGN_REM` is a literal mirroring the shell's, pinned to 12 by a test, and every length goes through `core::design_px`.
- `decimate` is min-max per pixel column with a `Point::BREAK` at a `NaN` run, never lyon's collapse. **Two caches stand between the model and the frame and nothing O(the data) may be REBUILT on a frame that changed nothing:** the paths behind gpui-component's `PathCache` (`element::rebuilds()` counts misses), keyed on `(model.version, slot.number, pane, view.key())` plus the plot rect's `x/y/w/h` — a percentile's key is `(version, slot.number, percentile index)` plus its own `y` and the plot's `x`/`w`, and neither path key carries a rem or bounds term of its own (the rem reaches them through the rect) — and the chrome — the four side `LinearScale`s, their y ticks, the tick labels and the x ticks — behind `chrome_key` in the element's `Buffers` (`element::chrome_rebuilds()`), keyed on `(version, view.key(), offset_secs, buckets.len(), bounds w, bounds h, rem)`; `an_unchanged_frame_rebuilds_nothing_and_a_moved_view_rebuilds` pins both counters. No key carries `axis_mode` or `step_us`, so **the module must bump `ChartModel.version` on ANY model change**. **"Rebuilds nothing" is not "allocates nothing"** — `Window::paint_path` takes its path by value, so a cache HIT still clones and translates it (one vertex `Vec` per painted path, bounded by the decimated point count), beside the chrome `Vec`s the component's own `Grid`/`PlotAxis`/`PlotLabel` take; both are the pinned API's price, and the counters pin the rebuild claim alone.
- `Layout::solve` reserves an axis column when EITHER pane uses that side, so both panes share one x mapping; the lower pane exists only while a visible slot uses a bottom axis, the density strip only while a visible slot HAS bins, and `split` clamps to `0.2..=0.8`. Ticks are the finest unit with `MIN_TICKS` = 3 candidates that already fit `TICK_GAP`, else the coarsest that still keeps three once thinned, else the finest pair, else one day tick — and never a unit FINER than the data's own step (`resolution_floor`, or a daily chart labels its days `00:00`). A bucket's x is its slot's CENTRE, and a percentile line outside its pane is SKIPPED before the cache, line and tag together (the density bars clamp instead).
- Each pane's data painting is clipped to its own rect through `Window::with_content_mask` — lines, percentile paths and tags to the plot, the density bars to the STRIP (a column beside the plot, so the plot's mask would erase them) — because the element's own mask is the whole element and a polyline built from bucket CENTRES overhangs by up to half a bucket, a quarter of the plot's width at the zoom floor. A tag whose lift would leave the pane drops below its line instead. **At most `MAX_DENSITY_QUADS` = 2,000 bars per FRAME** across both panes, in slot order: a bar is an uncached `paint_quad`, nothing in the model bounds slots × bins, and the spike disqualified per-cell quads past ~5,000 (`element::density_quads()` counts them; Part 4 owns the slot count). **`ChartElement::new`'s `ElementId` must be unique among the window's charts** — `Buffers` and both `PathCaches` hang off it, so two charts sharing an id serve each other's paths; a tile passes its `TileId`.

## Architecture

Cargo workspace with strict layering, enforced by crate visibility:

```
geode-app          the binary: wires shell + modules + services together
  ├─ geode-shell   tiling WM, workspaces, palette, keymap engine, scope/as-of state, theming
  ├─ geode-widgets shared widgets: a pure core + colour-parameterised painter each (the date-time field); below the shell, depended on by the shell and geode-marketdata
  ├─ geode-blotter any view definition as a collapsible, keyboard-driven hierarchy (Phase 3)
  ├─ (modules)     future per-module crates: config editor, diagnostics…
  ├─ geode-data    DataService: sources, ingestion, DuckDB, archive, query API
  └─ geode-core    shared vocabulary: types, config model, ids, errors, perf utilities
geode-demo-data    deterministic seeded synthetic risk data (SoA) + the criterion bench harness
```

**Dependency rules:** `shell` and `data` never depend on each other, and never on modules; `geode-app` is the only crate where everything meets. No crate other than `geode-data` may open a file or socket — modules only ask DataService.

**Threading model (spec §2):** UI thread (gpui — renders, owns entity state, only ever reads prepared immutable snapshots) / query pool (DuckDB read connections, results delivered as immutable columnar snapshots over channels) / ingest (background writers publishing generation-stamped tables). Performance budgets in spec §7 are contracts: <8ms pure-UI actions, <50ms requery at 1M rows, ingest never drops a foreground frame.

**Testing strategy (spec §10.3):** test weight goes data layer ≫ shell logic ≫ modules. Shell logic (tiling tree, keymap resolution, config merging) is pure logic designed to be testable without a window; modules use gpui `TestAppContext`. TDD per house rules.

**A green suite proves less here than you would expect, and `scripts/mutation-check.sh` is the answer.** Five review rounds on the query path each found Critical, silent wrong-data defects, and the cause was the same every time: a fixture that could not reach the defect. The harness breaks one load-bearing behaviour at a time and runs the suite — a `SURVIVED` line is a branch no test can see. Run it after touching the compiler, scope lowering, as-of routing, publish, retention, discovery or the grain vocabulary, and **add an entry for every behaviour you change**. Its header documents the rules learned the hard way; the two worth knowing up front are that a test asserting on *markers* will not notice a wrong *value*, and that an entry can lie in four ways — no test behind it, two defences overlapping so neither is isolated, a mutation that breaks something other than what its name claims and is "caught" for the wrong reason, or an anchor that matches its file twice, so the FIRST match is mutated whichever site that is (`--anchors-only` reports stale and duplicated anchors in under a second and exits non-zero on any; run it before every merge — it found nine duplicates on 2026-09-09, one of which had been guarding the wrong site). An entry's optional 6th argument names the specific test expected to catch it, so day-to-day runs (especially `--changed`) check that one test before falling back to the full crate suite. **Commit before you mutate:** restoring a mutated file with `git checkout` discards uncommitted work with it.

## Workspace invariants and gotchas

- **Every gpui-kit and gpui-pre crate is `=`-pinned in the root `Cargo.toml`** — `gpui-component`, `gpui-kit-assets`, `gpui-base`, `gpui-component-macros`, `gpui-pre` (aliased `gpui`) and `gpui-pre-platform` (aliased `gpui_platform`), all from crates.io since 2026-09-18 (0.6.2 / 0.3.5; spec `docs/superpowers/specs/2026-09-17-geode-gpui-kit-upgrade-and-adoption-design.md` §2). gpui-kit depends on `gpui-pre` with a caret and gpui-component names its own siblings `gpui-base`/`gpui-component-macros` with a caret too, so an unpinned entry would let `cargo update` move gpui — or split the gpui-kit family — under us (it did, on the first build of this upgrade). Bump both families together, deliberately, on a branch; read the gpui-pre crate's description on crates.io for the zed rev it snapshots. There is no git dependency on zed or gpui-kit any more, so the old two-copies hazard the previous form of this rule guarded against cannot recur. The full explanation is in the comment in the root `Cargo.toml`. **Glossary:** wherever this file or a code comment says "the pinned rev", "the pinned release" or "the pinned gpui-component", it means these exact versions; the source a maintainer reads is the registry copy at `~/.cargo/registry/src/*/gpui-component-0.6.2/src/` (styled components), `gpui-base-0.6.2/src/` (unstyled behaviour) and `gpui-pre-0.3.5/src/` (gpui itself), and the sibling `gpui-pre-*-0.3.5` crates beside them for anything gpui itself re-exports, never a git checkout.
- **Every new lib/bin target needs `bench = false`** (and `[[bench]]` targets need `harness = false`) so `cargo bench` runs criterion cleanly instead of the built-in libtest harness. This is a workspace-wide invariant — copy the pattern from any existing crate.
- `gpui_platform` uses the `runtime_shaders` feature so Metal shaders compile at runtime without a full Xcode install (no-op off macOS).
- In `main`, `gpui_component::init(cx)` must run before any component use, and the root view is wrapped in `gpui_component::Root` (which also renders the dialog/notification layers).
- Dialogs open through `shell::dialog::open_shell_dialog`, never `window.open_dialog` directly — it's the one standard door that cancels pending keymap sequences and closes an open palette before setting `ShellView`'s own `modal` state. **It also calls `window.prevent_default()` (2026-09-19): a dialog opened from a mouse-down that focuses its field — the scope bar's chips and grouping readout — would otherwise lose that focus to the shell root's bubble-phase focus grab on the same mouse-down (gpui focuses the `track_focus`ed element under the pointer unless an earlier listener prevented it), and typing after the click went nowhere; the sidebar gear goes through the same door but opens root-focused and was never broken. A new mouse-opened dialog must go through this door, and a test for one must type after the click, not just assert the state is `Some`.** Modals are Geode's own instant, self-owned overlay (backdrop + panel painted directly in `ShellView::render`, palette-style — no animation), not gpui-component's `Dialog`: that component hardwires a 250ms entrance animation with no opt-out at the pinned rev, which read as slow next to the instant palette, so this crate stopped routing through it for its own modals.
- `geode_demo_data::write_csv` does no quoting/escaping — it relies on all string columns drawing from fixed comma-free vocabularies. Revisit if a vocabulary ever grows free-form values.
- Release and bench profiles keep debug symbols on purpose (profiling support, spec §7.4).
- **A tile occupant that tracks its own focus handle takes focus on any mouse-down, a drag grab included; every tile mouse-down path re-arms `pending_focus_restore` so the shell's chords survive — the two `on_mouse_down` listeners in `render.rs` and `try_arm_tile_drag` (`drag.rs`), which returns before the click-to-focus tail and so has to arm it itself. Keep all three — and `try_fullscreen_on_double_click` (`drag.rs`, 2026-09-19: `mod`+double-click is the mouse form of `mod+f`), which both listeners call AHEAD of the drag arm and which arms it too: the pair's second click is a mod+down the arm would otherwise claim, and the arm refuses while fullscreen, which is exactly when the toggle has to run to restore the layout; it routes through `dispatch` with `workspace::fullscreen_tile`'s own id so session dirt, the action tail and the log line come from the one chain, and it refuses a docked tile through `focus_main_tile`'s membership answer since fullscreen is main-tree-only.** The consumer has one exception (user ruling 2026-09-17): `render` clears the flag but **withholds the focus move only while the focused tile's occupant itself HOLDS the focused handle in insert mode** (`occupant_holds_insert_focus`, `occupants.rs` — `TileContent::holds_focus` answered by that occupant for the focused handle, which being its own input is never a shell surface, and `mode == insert`; the insert branch's own predicate, shared so the two cannot drift), which is what lets a module open an editor from a double-click without it going deaf a frame later; out of insert mode the restore runs exactly as before. Two different backstops sit under them, and they are not interchangeable. `render`'s `window.focused(cx).is_none()` net covers only a focused handle that was actually **dropped** — a focus-tracking tile *closed* while focused — because a dropped handle is the one thing that makes `Window::focused` report `None`. It cannot see a **workspace switch**: `ensure_occupants` retains occupants for tiles in every workspace, so a switched-away view is unmounted but alive, focus stays `Some`, and gpui silently falls back to `root_node_id` dispatch — which carries none of the shell's key listeners, so every chord dies. That case is caught in `ensure_occupants` itself, at the point where tiles leave the visible set: if any did and window focus is on a handle that is none of the shell's own (`focus_handle` plus the four `Entity<InputState>`s — see `holds_shell_focus`), the shell root takes focus immediately, not via the flag (which is consumed at the *top* of render and would be a frame late). Both conditions are deliberately narrow: anything broader would yank the caret out of a live focused `Input`. **The keyboard has the same rule (2026-09-14, Part 3's final review, I-3): every verb that moves which TILE has focus re-arms `pending_focus_restore` through `ShellView::note_keyboard_focus_move` (`occupants.rs`) when window focus is on a non-shell handle** — one door, called from `dispatch`'s `apply_workspace_action` branch (the four directions, the workspace switch, a dock show/toggle/move, a close) and from `open_module`'s focus-an-existing-tile arm; without it, `i` then `mod+l` moved the focused tile while the abandoned cell editor kept WINDOW focus, so every following bare key was dispatched by the matcher AND typed into that cell, count prefix and all. The editor is left open on purpose — it belongs to the module until commit or cancel, and `escape` on the tile once focus returns there still cancels it through the module's own fragment binding. (A keyboard focus move arms the flag with the OLD tile's editor focused; the 2026-09-17 exception on the consumer is withheld only while the focused tile's occupant itself HOLDS the focused handle in insert mode, and the newly focused tile holds nothing — even if its own abandoned editor still reports `mode == insert` — so the restore runs.)
- **Chords still dispatch from the scope bar's text field (2026-09-12).** `handle_key_down`'s filter-focused branch resolves any keystroke carrying ctrl, alt or cmd (`Modifiers::is_chord`; shift alone is typing) as a single keystroke through `single_keystroke_binding` against the `workspace` context alone, never `context_stack` — the focused tile's own bindings (a blotter's `ctrl+d`) must not fire behind a trader's typing — and reflects the frame's text back into the field afterwards, the one focused-field write outside the field's own typing. Bare keys and shift-only keys still go to the field untouched; the command line keeps only its palette-toggle exception; a modal owns the keyboard outright. **An overlay opened from the field returns focus to it on close** (same day's second ruling): `overlay_return_to_filter` is recorded by the palette's open arm and the dialog door and consumed by `return_focus_from_overlay`, the one door `close_modal` and `close_palette` both use. `close_palette` moves focus only when a palette was actually open — the dialog door calls it unconditionally, and an unconditional root focus there blurred the field a line before the door asked whether it held focus.
- **A list row's state colours come through `geode_shell::shell::listrow::row_paint` (2026-09-19, design-guide audit): the highlighted row is `list_active` under `foreground`, the pointer's row `list_hover`, and a fuzzy-match glyph `accent` — `primary` floored against the active row's ground.** Every row list — the palette, the settings/keybindings/object dialogs, the picker's two stages, the as-of presets, the command line's completions — paints `if highlighted { bg(active).text_color(text) } else { hover(|s| s.bg(hover)) }`, so the state and the pointer are two distinct fills and every clickable row answers the pointer (there was no hover feedback anywhere before). Do not go back to `theme.selection` under `theme.primary`: `selection` is gpui-component's TEXT-selection colour, not a list token, and `primary` over it is under 3:1 on 15 of 44 bundled themes (Fahrenheit 1.53:1) — the row a trader is about to `enter` was the least readable one in the list; `foreground` clears the floor over both list tokens on all 44 (`every_row_state_is_readable_on_every_bundled_theme`, no exception list; `the_retired_pairing_still_fails_the_sweep` keeps the floor honest). Builders called from closures (`picker::build_columns`/`build_values`, `asof_view::build_presets`) take a `RowPaint` (`Copy`) in place of the old `primary`/`selection` pair. In-app controls use the arrow cursor: the six `cursor_pointer()` sites (workspace tabs, settings gear, scope chips, value chips, ticks, chevrons) are gone — the guide reserves the hand for links. **The same guide owes every control a hover AND a pressed state, and a clickable element that is not a list row or a gpui-component `Button` gets both through `geode_shell::shell::control` (2026-09-19, user finding): `control::paint(theme, Rest, surface, text)` — `Rest::Filled(fill)` for a chip with its own fill, `Rest::Bare` for a glyph on the surface — borrows the secondary `Button`'s `secondary_hover`/`secondary_active` or the ghost's `accent` ONLY where the token is ≥ 1.10:1 (`DISTINCT_RATIO`) from the rest fill, else steps the rest fill toward `foreground` until it is (on 6 of 44 bundled themes `secondary_hover` IS the rest fill, on 28 it is within 1.10:1 — a borrowed token alone leaves the hover invisible); pressed is also ≥ 1.05 (`PRESSED_STEP`) from hover. Everything is composited over the control's SURFACE (`title_bar`, `sidebar`, `status_bar`, `popover`, `table`), never `background`; the control keeps its OWN text on every state (a ticked tick stays `success`), floored to 3:1 over that state's fill. `PointerStates::pointer_states` applies both as gpui `hover`/`active` refinements on a `Stateful` (id'd) element — at the pinned rev a stateless element's hover never repaints, and a second `.hover()` on the same element is a debug assertion. `ControlInputs` is every colour the derivation reads, the memo key a per-row painter (the blotter chevron) compares instead of re-deriving. A child `Icon` must inherit the box's `text_color`, never pin its own, or it will not recolour. Selected, open and disabled states take no hover (the active workspace disc, the open `⋯` menu), and neither does anything without a listener — a hover promises a click; the market-data popup rows take none either, since `menu_hover` already moves the highlight under the pointer. The stack marker every occupant's header paints is a clickable `Tone::Neutral` chip and goes through `control::for_chip`, the bridge from a `ChipPaint` to its states. Two sweeps with no exception list, `every_control_state_is_readable_on_every_bundled_theme` and `every_control_state_is_distinct_from_rest_on_every_bundled_theme`, run over `shipped()`, the list of every (rest, surface, text) a site hands in — a new site adds its pairing there.** Palette titles that open a dialog end in `…` (`Open settings…`, `Keyboard shortcuts…`, the six `Edit …`, `Pick a dimension…`, `Jump to a point in time…`); a dialog's own title does not. Empty states name the next action where there is one (`no views are configured — n creates one`; the schema's stays bare).
- **Chrome geometry is on the rem scale through `geode_shell::shell::scale` (2026-09-19, design-guide audit); radii come from the theme.** Every chrome length — dialog widths, row heights, the status bar, the sidebar rail, the command-line strip, tile header/footer strips, the market-data popup — is authored in pixels at the `FontSize::Medium` rem (`DESIGN_REM` = 12, pinned to `FontSize::Medium.rem_px()` by a test) and resolved through `scale::design(px)` (→ `Rems`) or `scale::design_px(px, rem_size)` (→ `f32`, for window-pixel arithmetic: `content_area`, `commandline_view`, the overlays' margins), so `Small`/`Large` scale the frame with the text inside it instead of leaving a 44 px row sum around rows that grew. `sidebar::width(window)`/`status::height(window)` are the rem-aware reads the tile surface and every window test use; `sidebar::WIDTH`/`status::HEIGHT` are the design-rem literals. At `Medium` every length is pixel-identical to the literal it replaced — the row-height sums (`ROW_HEIGHT` × rows) were kept as sums, on the scale, not replaced by `max_h`, because they are the tuned layout and only their unit was wrong. What stays `px`, on purpose: tile rectangles from the pure layout, hairlines and the 2 px divider, the drag-hit tolerance, the overlay shadow, `AS_OF_STRIPE_HEIGHT`, the blotter delegate's whole tree cell (column widths are the `view_presentation.toml` pixel contract, and its indent/gutter/chevron live inside that width — scaling them alone would only overflow it sooner), `dialog.rs`'s `gap(px(6.))` that hand-matches `Input`'s own fixed prefix gap, gpui-component's own `TITLE_BAR_HEIGHT`, the drag ghost (an outline with no text), and the market-data panel's `LABEL_WIDTH`/`CELL_WIDTH` — a known gap: `TableDelegate::column` has no window to read a rem from, so at `Large` a panel cell's text grows inside a column that did not (fix: a rem handed to the delegate per render plus `refresh`; deferred). Radii: `theme.radius` for rows and chips (6 px on every bundled theme — none sets `radius`), `theme.radius_tokens().sm` for small pills and the swatch, `theme.radius_lg` for panels; `rounded_sm()`/`rounded_md()` (gpui's Tailwind values, not the theme's) are gone. Helpers that take colours as parameters (`key_chip`, `value_chip`, `hint_rows`, the toolbar's `chip`, the picker's builders) take the radius the same way, because they are called from closures that cannot borrow the theme. One length has ONE owner: the status bar's wrapper (`shell-status-bar`) declares the height and the inner `StatusBar` is `h_full` — a duplicate declaration survived the harness because the test measures the wrapper. Where two declarations are unavoidable — the sidebar rail's painted width against `content_area`'s reservation, the command-line strip's painted height against the `strip_top` computed from it — the zoom test measures the PAINTED element against the reservation, because the review found both mutations survived a test that only re-checked the arithmetic (six `scale:` harness entries). `chrome_and_dialog_rows_follow_the_font_size` is that test: it steps to `Large` and checks the settings list, the status bar, the painted rail and the command-line strip all scale by 14/12, the bar still meets the viewport bottom and the strip still ends on the focused tile's bottom border. Two visual changes at `Medium` ride along and are deliberate: rows and chips went from 4 px to the theme's 6 px radius, and `rounded_sm()`'s 1.5 px pills to the token's 3 px. The market-data `⋯` popup and picker paint gpui-component's own `popover_style(cx)` (`ThemeStyled`) with `PopupMenu`'s row geometry (26 px rows, 8 px inset, `theme.radius`, `accent`/`accent_foreground` highlight, its separator) on the scale — the design guide's "preserve the component family's geometry".
- **A semantic chip's colours come through `geode_shell::shell::chip::chip_paint` (2026-09-19, design-guide audit) — never `warning_foreground`/`danger_foreground` over a tint by hand.** Those tokens are for text on a SOLID fill and fall back to `primary_foreground` (the background family) at the pinned rev, so over a 25% tint they read ~1:1 — under 3:1 on 30 of 44 bundled themes; the market-data panel found it on its cells (`cell_paint`) and the door makes the fix the rule for the blotter's `pinned`/`unscoped`/`filtered`/`AS OF`, the diagnostics `filtered` pill and its warning/error rows, the toolbar and status-bar as-of chips and the scope bar's contradiction chip. `Tone::{Warning, Danger}` are tinted fills with `foreground` text; `Tone::{WarningText, DangerText}` are the semantic colour as bare text, floored to 3:1 against `background` (ten bundled themes ship `warning` faint); `Tone::Neutral` is the theme's `secondary` pair for a state the trader chose — the blotter's `pinned` and `filtered` pills and the diagnostics `filtered` pill wear it (2026-09-19), so `unscoped` and `AS OF` are the only warning-toned things in a header strip (the guide's emphasis budget; the per-tile `AS OF` chip was kept by user ruling the same day, the window stripe, toolbar chip and status segment beside it). `every_chip_tone_is_readable_on_every_bundled_theme` sweeps every tone on every theme with no exception list, and `the_retired_pairing_still_fails_the_sweep` proves the floor bites — a new tone that does not clear the sweep cannot ship. Market-data keeps its own `cell_paint`/`FlooredTones` (same rule, its own sweep tests).
- **`DataTable` is never focused; its key context is bound to `NoAction` in `geode_blotter::init`, and a tile click re-arms the shell's focus restore.** Same door and reasoning as `geode_shell::shell::dialog::init_reclaimed_keybindings` — the table would otherwise swallow the vim-idiom keys the blotter's own bindings depend on.
- **A chevron click and a row double-click are `space` (2026-09-12): both go through `BlotterTile::expand_at_cursor`, the one path `zo`/`zc`/`za` also take.** The chevron listener in `BlotterDelegate::render_td` has no route to the tile but an event on the `TableState` it renders into, and `TableEvent` is gpui-component's closed enum, so the blotter emits its own `ChevronClicked` through a second `EventEmitter` impl on `TableState<BlotterDelegate>` (the orphan rule allows it: the event type is local). The listener stops propagation and ignores `click_count() > 1`, so a fast double-click on the chevron toggles exactly once rather than twice or three times — keep both halves.
- **A `NonAttributable` cell is NULL — read only through `f64_at`/`f64_value`; the blotter's cache is the one place a cell becomes text.** Reading a numeric column any other way (e.g. an `Array`'s own getter, which reads the underlying storage regardless of nullness) risks painting `0.00` for a cell the compiler explicitly declined to sum.
- **`FrameVersions.flip` is excluded from `BlotterTile::follows_changed` on purpose.** It only signals a tile with an already-staged snapshot that it is safe to promote (Phase 4a's flip barrier); a tile that adds it to `follows_changed`'s comparison requeries on every flip instead of just promoting.
- **`pending_tiles` is keyed by `TileId` and `unplaced_records` by the raw `u64` (the session's key type); both are retained to live tiles at the end of every `ensure_occupants`.** A request for a closed tile is dropped, never re-aimed.
- **Showing a dock exits fullscreen** (`Workspace::toggle_dock`): a fullscreen main tile plus a focused dock painted no focus ring and left `mod+f` dead; the show branch clears fullscreen first, the same way `move_to_dock` does.
- **`[ui] line_numbers` reaches modules as the `geode_shell::linenumbers::UiSettings` gpui global, the keymap's bindings as `geode_shell::tips::Chords`, and `[time]` as `geode_shell::clock::AppClock` — the workspace's THREE globals, all written only by the shell (startup and reload) and only read by modules.** The shell writes `UiSettings` (startup, the settings row, `ui::line_numbers_cycle`, hot reload) and the blotter observes it with `observe_global`; `AppClock` is written at startup and on a `[time]` reload only (never per-frame), and a module reads it with `cx.try_global::<AppClock>().map(|c| c.0).unwrap_or_else(|| Clock::machine().0)` — `try_global`, since a module test fixture may never have installed it — and follows it with its own `observe_global` to repaint or rebuild on a zone change. A module has no path to `ShellView`, and `ConfigReloaded` only fires for a `views`/`dimensions` reload, so neither existing route could carry a settings-row step or a zone change to a live tile. Keep these the only globals unless the state is genuinely app-wide and module-visible. The blotter's gutter is painted inside the tree cell, not a column: `BlotterDelegate::column` widens the tree column by `gutter_px()`, and `on_ui_settings` must call `TableState::refresh` because the pinned gpui-component caches `column()`'s width in `col_groups`. Known, inherited trade-off: every keyed persist (`find_style`, `font_size`, `add` direction, `line_numbers`) spawns its write unordered, so two rapid steps can land the older value and the reload will re-derive it — a fix belongs in `config_write`, for all four at once.
- **Test fixtures bind `ctrl+v`/`ctrl+h` in a test layer** (`shell/tests/mod.rs::TEST_ADD_KEYMAP`) to `tile::add_rec_horizontal`/`_vertical`; the shipped keymap has no create-a-tile chord. `test_services()` carries a `rec` recording factory in its roster because an add on a focused placeholder fills it in place.
- **If you change `examples/demo-config/datasets.toml`'s columns — a column's `role`, `grain` or *order* included, not just the column set — delete the demo/probe database first.** `apply_schema` is `CREATE TABLE IF NOT EXISTS`, so an existing table is never migrated — a grown schema fails every publish with "table ... has N columns but N+1 values were supplied". A role change alone grows tables: making `strike` a carried dimension (2026-09-12) added it to every finer grain's table, where as an attribute it had lived in the instrument table only. A reorder is the quiet one: `publish_file` moves rows **positionally** (`insert into {live} select *, …` from staging, and the outgoing generation likewise `select *` into the archive) and both `create_table_sql` and `create_document_table_sql` emit their payload columns in TOML file order (`preserve_order` is on workspace-wide), so swapping two same-typed columns in `datasets.toml` against an existing database raises no error at all — it files each one's values under the other's name. `--demo`'s database lives at `$TMPDIR/geode-demo/<rows>-<seed>/geode.duckdb` (`geode-app::demo::demo_dir`, seed fixed at 42); delete that whole `<rows>-<seed>` directory, since the generated source CSVs under its `src/` are keyed to the same schema.
- **A module's insert mode is a tile-owned, focused `Input`; `ShellView::handle_key_down`'s insert branch is what lets it type at all** (`shell/input.rs`, after the filter-field branch, before the matcher): while a context on the stack carries `mode == insert` and window focus is on a handle the shell does not own, only single-keystroke bindings resolve (a chord against the whole stack, a bare key against only the insert-mode contexts) and everything else propagates to the input untouched. **A dropped `InputState` does NOT return focus by itself at the pinned gpui-component rev — `Root` holds a focused input strongly and only unregisters it from that input's own render, which a removed input never reaches.** An occupant must `window.blur(cx)` *then* drop the entity, in that order and both halves; skipping the blur leaves the handle alive, `Window::focused` never reports `None`, and the shell's own focus-return net (this file's `render`'s `is_none()` net, above) never fires — every chord dies for the rest of the session. `MarketDataTile::close_editor` and `geode_shell::module::recording`'s fixture are the two implementations; a third module doing text entry owes the same sequence.
- **A keymap fragment's predicate must be a plain conjunction — no `!`, `||` or `(` anywhere in it — or `keymap::fragments::check_fragment` drops the binding with an error diagnostic.** The check is textual (the predicate's first identifier), not a walk of the compiled boolean tree, so `blotter || workspace` and `(!blotter)` both pass a naive "starts with my context" test while actually binding in every context but the module's own tile — the widest possible shadow, from the one layer a trader cannot open to unbind it. Refusing every occurrence of the three tokens (not just a leading one) is what makes "a fragment can never shadow a shell binding or another module's" hold in fact rather than in the common case; do not loosen it to a leading-token check again.
- **`ModuleFactory::contexts()` is a separate answer from `kind()`** because a module's kind and the context its fragment binds can genuinely differ — the market-data panel factory is kind `cvi` (one roster entry per document kind) but returns `vec!["marketdata"]` from `contexts()` (one vocabulary shared by every document kind's panel); the default `vec![kind]` would silently drop every fragment binding for it, since `check_fragment` refuses one whose first identifier is not among the factory's own contexts.
- **Keybindings reset (2026-09-19): `r` removes the row's whole override SET (`KeybindingRow::overrides`, from `keymap::user_overrides_for` over the entire keymap), never the row's displayed binding** — a rebind of a builtin is two user keys (the new one and the `"none"` shadow over the old) and removing only the displayed one leaves the action unbound, not reset; a `d`-shadowed row displays nothing and still resets. Removals are keyed by `Binding::key_source` (the file's spelling), `apply_reset` never creates an entry. `shift+r` is reset-all (`Verb('R')`, the one shifted verb in `dialogmode`): `apply_reset_all` drops every `[[bindings]]` entry from the user `keymap.toml` — hand-written included, by ruling — and nothing else; armed and buttoned only while `user_binding_count > 0`.
- **The keybindings dialog reads a fragment binding as `Layer::Builtin`**, the same layer the shell's own shipped keymap reports: `r` (reset) removes a user override and lets the fragment show through again, and `d` (unbind) writes a user-layer `"none"` shadow over it rather than trying to remove a binding the trader's own config does not own — see `d_over_a_modules_fragment_binding_writes_a_user_layer_shadow` and `r_removes_a_user_override_and_the_modules_fragment_shows_through` in `crates/geode-shell/src/shell/tests/keybindings_dialog.rs`.

## gpui skills

The `gpui-kit` and `gpui-kit-design-guides` skills (available via the Skill tool) are vendored into this repo from longbridge/gpui-kit and tracked in `skills-lock.json` (they replaced the retired `gpui` and `gpui-component` skills on 2026-09-17, with the upgrade to the crates.io releases). Use them when touching any gpui rendering, entity, async, focus, or component code. **One translation to keep in mind:** the skills are written for the `gpui-kit` umbrella crate and spell paths as `gpui_kit::component::X` / `gpui_kit::base::X`; Geode does not depend on the umbrella (see the dependency comment in the root `Cargo.toml`), so those are `gpui_component::X` and, for the unstyled layer, a re-export or `gpui_base::X` here — the item names and signatures are the same, only the prefix differs.
